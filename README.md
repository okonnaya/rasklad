# Расклад

Медиа о таро. Статический сайт на React и Webpack, контент хранится в SQLite.

## Запуск

Нужны Node.js 22 и Python 3.9+ (SQLite входит в стандартную библиотеку Python).

```sh
npm ci
npm start
```

`npm start`, `npm run watch` и `npm run build` автоматически выгружают контент
из `database/rasklad.sqlite3` в `src/data/*.json`. Браузер получает данные в
составе сайта, поэтому работа сайта не требует соединения с Airtable.
После редактирования базы во время работы dev-сервера выполните `npm run db:export`.

## База данных

В базу перенесена существующая копия данных проекта: 78 карт, 3 расклада и
3 статьи. Изображения находятся в `src/data/`. Свежесть данных относительно
Airtable не подтверждена: 11 сентября 2026 года исходный токен вернул HTTP 401.

Таблица `content` хранит коллекцию, идентификатор, порядок и JSON записи,
сохраняя все исходные поля и типы без потерь. Представления `tarot_cards`,
`fortune_tellings`, `articles` позволяют просматривать коллекции через SQL.
`metadata` хранит источник и дату переноса. После успешного импорта из Airtable
таблица `airtable_records` также содержит полные исходные записи, включая поля,
которые пока не используются сайтом.

```sh
npm run db:status  # количество записей и источник
npm run db:export  # выгрузить содержимое базы для сайта
npm run test:db    # проверка переноса, целостности и обработки ошибок
npm run build     # собрать сайт в docs/
```

База уже включена в репозиторий. `npm run db:seed` нужен только для первичного
создания отсутствующей базы из JSON; он отказывается перезаписывать данные.
Можно открыть SQLite любым совместимым редактором и менять записи в `content`.
При изменении изображения положите соответствующий файл в `src/data/`.

## Повторный импорт из Airtable

Скопируйте `.env.example` в `.env.local`, если локальной конфигурации ещё нет,
и заполните `AIRTABLE_TOKEN`. `.env.local` исключён из Git. На текущем компьютере
прежний токен уже сохранён в этом файле; другие найденные значения сохранены
в игнорируемом `.airtable-tokens.local.json`. Значения из окружения имеют приоритет.

```sh
npm run db:import
# Совместим со старым способом запуска:
node src/updateAirtableData.js
```

Импорт читает все страницы трёх таблиц, скачивает изображения, проверяет записи
и заменяет содержимое базы. Ошибка получения данных останавливает импорт до
изменения рабочей копии. Перед успешной заменой сохраняется локальная резервная
копия `database/before-import.sqlite3`. Затем создаются JSON для сайта.
После импорта выполните `npm run build` и сохраните базу, JSON, изображения и
сборку в Git. Удалённый Airtable при импорте не изменяется.

GitHub Actions можно запустить вручную с секретом `AIRTABLE_TOKEN` и, если база
другая, переменной `AIRTABLE_BASE_ID`. Результат доступен как артефакт; workflow
не создаёт коммиты от бота и не публикует сайт автоматически.
